# 智能在线学习考试平台开发计划

## 1. 项目目标与实施原则

本计划依据《项目说明.md》制定，目标是完成一个采用模块化单体架构的 MVP，打通以下核心闭环：

1. 用户注册、登录及角色权限控制。
2. 发布者上传学习资料，管理员审核后发布。
3. 用户免费学习或模拟付费购买资料，并记录学习进度。
4. 发布者创建题目、固定试卷和考试，指定考生参加。
5. 考生在线答题，系统自动保存、自动交卷、客观题自动评分，发布者批改主观题。
6. 用户查看成绩与解析，发布者查看考试统计。
7. 用户购买并使用 AI 次数，进行资料总结和知识讲解。
8. 管理员管理用户、内容、订单、AI 配置和操作日志。

首版不实现多租户、班级管理、直播、随机组卷、批量导题、智能推荐、AI 出题、AI 考试分析、智能监考、证书、申诉、创作者结算、优惠券、发票、Elasticsearch、向量数据库和微服务。

## 2. 当前项目起点

- 前端目录：`frontend/learning_platform_frontend`，已有 Vue 3 + Vite + TypeScript 基础工程。
- 后端目录：`backend`，目前只有 IDEA 工程配置，需要创建 Spring Boot Maven 工程及代码结构。
- 开发工具：前端使用 VS Code，后端使用 IntelliJ IDEA。
- 数据与基础服务：MySQL、Redis、MinIO。
- MVP 支付方式：优先采用模拟支付，不接入真实支付渠道。
- AI 接口：先抽象统一 AI 服务接口，具体模型、密钥和地址由配置文件或环境变量提供。

## 3. 两种角色的职责边界

### 3.1 AI 开发的内容

- 分析需求、设计模块、接口、数据模型和状态流转。
- 在项目目录内创建、修改前后端源代码和配置模板。
- 编写数据库建表 SQL、初始化数据 SQL、接口文档和部署说明。
- 编写单元测试、接口测试及必要的测试数据脚本。
- 执行可在命令行完成的构建、静态检查和自动化测试，并修复代码问题。
- 根据你提供的运行日志、截图和报错继续排查及修改。

### 3.2 你需手动操作的部分

- 在 VS Code 和 IDEA 中打开工程、选择本机 SDK/JDK、运行或调试项目。
- 安装并启动 MySQL、Redis、MinIO，创建数据库、账号、存储桶并执行 AI 生成的 SQL。
- 将本机数据库密码、JWT 密钥、MinIO 密钥和 AI API Key 写入本地环境变量或私有配置；不要将真实密钥提交到 Git。
- 在需要 IDEA 图形界面、数据库管理工具、浏览器或第三方平台控制台时完成点击、授权和配置。
- 准备真实测试文件、视频、PDF、封面等业务素材。
- 按验收清单进行人工页面体验和业务确认，并将问题反馈给 AI。
- 若未来接入真实支付、域名、HTTPS 或云服务器，由你申请账号、完成实名认证、购买资源并配置密钥。

## 4. 分阶段开发步骤

## 阶段 0：需求冻结与工程约定

**目标：** 明确 MVP 边界、开发规范和联调规则，避免开发中反复改动基础设计。

### AI 开发

1. 整理三类角色：普通用户、发布者、管理员，并形成权限矩阵。
2. 定义学习资料、题目、试卷、考试、订单、权益、AI 任务的状态枚举及合法流转。
3. 统一接口规范：`/api` 前缀、REST 风格、分页参数、统一响应体、错误码和时间格式。
4. 统一代码规范、目录结构、命名规则和 Git 忽略项。
5. 明确本地开发端口、跨域方案和环境配置模板。

### 你需手动操作

1. 确认本计划中的 MVP 范围和模拟支付方案。
2. 确认本机可使用的 JDK、Node.js、MySQL、Redis、MinIO 版本。
3. 确定 AI 服务供应商及可用模型；若暂未确定，先使用模拟 AI 服务完成业务联调。
4. 确认是否允许普通用户申请成为发布者，或首版由管理员直接分配发布者角色。

### 完成标志

- 角色权限、状态流转、接口规范和环境约定已确定。

## 阶段 1：基础环境、后端骨架与数据库

**目标：** 前后端可启动，数据库和基础服务可连接，形成可持续开发的基础工程。

### AI 开发

1. 检查并整理现有 Vue 工程，安装并配置 Vue Router、Pinia、Axios、Element Plus。
2. 建立前端目录：`api`、`router`、`stores`、`views`、`components`、`layouts`、`types`、`utils`。
3. 在 `backend` 中创建 Spring Boot Maven 工程，配置 Spring Web、Validation、Spring Security、MyBatis、MySQL、Redis、JWT、对象存储客户端和测试依赖。
4. 按 `auth`、`user`、`content`、`learning`、`question`、`exam`、`grading`、`ai`、`order`、`admin`、`common` 建立模块化包结构。
5. 实现统一返回体、业务异常、全局异常处理、参数校验、分页模型和基础审计字段。
6. 设计并生成完整建表 SQL、索引、外键或逻辑关联、初始化角色及管理员数据脚本。
7. 为本地开发提供不含真实密钥的配置模板，验证 Maven 和 npm 构建。

### 你需手动操作

1. 使用 IDEA 打开 `backend`，选择 JDK 17 或项目指定版本，等待 Maven 索引完成。
2. 使用 VS Code 打开 `frontend/learning_platform_frontend`，安装推荐扩展，并执行 `npm install`。
3. 安装并启动 MySQL、Redis、MinIO。
4. 在 MySQL 中手动创建数据库和专用账号，执行 AI 提供的建表及初始化 SQL。
5. 在 MinIO 控制台创建私有存储桶，并配置允许的文件类型和容量策略。
6. 在本机私有配置或环境变量中填写数据库、Redis、MinIO、JWT 等连接信息。
7. 分别在 IDEA 和 VS Code 中启动后端与前端，反馈运行日志。

### 数据库表范围

- 用户：`user`、`role`、`user_role`。
- 学习：`learning_content`、`content_file`、`learning_progress`、`content_comment`、`content_like`、`content_favorite`。
- 考试：`question`、`question_option`、`exam_paper`、`exam_paper_question`、`exam`、`exam_candidate`、`exam_attempt`、`exam_answer`、`exam_result`。
- AI：`ai_task`、`ai_summary`、`ai_conversation`、`ai_message`、`ai_usage_record`。
- 订单：`product`、`orders`、`order_item`、`payment_record`、`user_entitlement`。
- 系统：`content_audit`、`operation_log`、`system_config`。

### 完成标志

- 前后端可以独立启动；后端健康检查成功；MySQL、Redis、MinIO 连接正常。

## 阶段 2：注册登录、用户与权限

**目标：** 建立平台安全基础，三种角色只能访问被授权的功能。

### AI 开发

1. 实现注册、登录、退出、刷新登录状态、获取当前用户和修改个人信息接口。
2. 使用密码哈希存储密码，使用 JWT 和 Spring Security 完成认证授权。
3. 实现普通用户、发布者、管理员的接口级权限控制和资源归属校验。
4. 实现验证码或登录防刷的 Redis 基础能力；开发阶段可配置关闭。
5. 开发登录、注册、个人中心页面，以及前端 Token 管理、路由守卫、请求拦截和 401/403 处理。
6. 编写认证、越权访问、参数校验等测试。

### 你需手动操作

1. 在数据库中确认初始化管理员账号和三类角色数据正确。
2. 在 IDEA 中运行安全相关测试，使用浏览器分别登录三类测试账号。
3. 手动验证错误密码、未登录访问、普通用户访问管理页等场景。
4. 若启用短信或邮箱验证码，申请第三方服务并配置凭证；MVP 可先使用图形验证码或固定测试验证码。

### 完成标志

- 三类用户能够登录；页面菜单、路由和后端接口均按角色正确限制。

## 阶段 3：文件上传与学习资料

**目标：** 打通“发布者创建资料—管理员审核—用户学习”的主流程。

### AI 开发

1. 实现 MinIO 文件上传、下载、预览、删除和临时访问地址，校验文件类型、大小和资源归属。
2. 实现学习资料草稿、编辑、提交审核、审核通过、驳回、发布、下架等状态流转。
3. 实现分类管理、资料列表、筛选、分页、详情和发布者工作台。
4. 支持图文、PDF/文档、视频和附件信息；首版不做复杂转码。
5. 实现免费资料与付费资料的访问校验，付费资料依赖用户权益。
6. 实现学习开始时间、最后学习时间、大致完成进度。
7. 实现收藏、点赞、取消操作、评论发布和评论列表，并处理重复操作。
8. 开发用户端资料列表、详情、在线学习、我的学习、我的收藏页面。
9. 开发发布者资料管理和编辑页面，以及管理员分类管理和资料审核页面。
10. 编写内容状态、文件权限、重复点赞收藏及越权编辑测试。

### 你需手动操作

1. 准备若干封面、图文、PDF、视频及附件样例。
2. 在 MinIO 控制台检查上传对象是否进入正确存储桶，且未产生匿名公开访问。
3. 使用发布者账号创建资料，再使用管理员账号审核。
4. 使用普通用户账号验证免费访问、无权益访问付费资料、学习进度、收藏、点赞和评论。
5. 确认浏览器是否能够正常预览目标格式；无法预览的格式首版采用下载方式。

### 完成标志

- 学习资料从草稿到审核发布的全流程可用；免费/付费访问控制正确；互动和进度可记录。

## 阶段 4：题库、试卷与考试发布

**目标：** 发布者可以创建题目、固定组卷、发布考试并指定考生。

### AI 开发

1. 实现单选、多选、判断、填空、简答五类题目的增删改查和选项维护。
2. 设计不同题型答案的统一存储格式，并防止正确答案提前泄露给考生接口。
3. 实现固定试卷创建、手动选题、题目排序、每题分值、总分计算和试卷预览。
4. 实现考试配置：试卷、起止时间、答题时长、及格分、指定考生、成绩显示规则。
5. 实现考试发布校验：时间合法、试卷非空、考生有效、考试发布额度充足。
6. 发布成功后原子扣除一次考试额度，失败或回滚时不扣除。
7. 开发题库管理、试卷管理、试卷预览和考试管理页面。
8. 编写试卷总分、资源归属、考试状态和重复发布测试。

### 你需手动操作

1. 使用发布者账号录入五种题型的测试题和答案解析。
2. 手动组成至少一份同时包含客观题与主观题的试卷。
3. 准备多个考生账号，并在发布考试时指定这些账号。
4. 校验考试起止时间、时区和本机系统时间是否一致。
5. 验证无考试额度时不能发布、有额度时扣减一次。

### 完成标志

- 发布者可以创建题目和固定试卷，使用额度发布考试并指定考生。

## 阶段 5：在线答题、交卷与阅卷

**目标：** 打通完整考试过程，并确保答案不易因刷新或网络中断丢失。

### AI 开发

1. 实现考生考试列表、考试说明、进入考试、开始作答和考试资格校验。
2. 服务端计算考试剩余时间，避免只依赖浏览器倒计时。
3. 实现答案即时/定时保存、断线恢复、刷新恢复、手动交卷和幂等提交。
4. 使用后端定时任务处理超时自动交卷；Redis 可缓存考试状态，MySQL 保存最终可靠数据。
5. 自动评分单选、多选、判断题；填空题按配置自动评分或进入复核；简答题进入人工阅卷。
6. 实现主观题阅卷、得分校验、批改完成状态和最终成绩生成。
7. 实现成绩页：总分、是否及格、正确/错误题数、每题得分、正确答案与解析，并遵守成绩显示配置。
8. 实现考试统计：参加、已交卷、未参加、平均/最高/最低分、及格人数/率、各题正确率。
9. 开发在线答题、阅卷、成绩详情和统计页面。
10. 编写重复交卷、越权考试、超时交卷、评分边界和并发保存测试。

### 你需手动操作

1. 使用多个考生账号完成完整考试，覆盖手动交卷和超时自动交卷。
2. 作答过程中刷新页面、短暂断网后恢复，检查答案是否保留。
3. 使用发布者账号批改填空/简答题，确认最终成绩生成时机。
4. 人工核对自动评分、总分、及格状态和每题正确率。
5. 验证未指定考生、考试未开始、考试已结束等异常场景。

### 完成标志

- 考生可稳定作答和交卷；客观题自动评分、主观题人工评分、成绩与统计正确。

## 阶段 6：商品、订单、模拟支付与权益

**目标：** 支撑付费资料、AI 次数包和考试发布次数包三类商品。

### AI 开发

1. 实现商品、订单、订单明细、支付记录和用户权益模型。
2. 实现创建订单、模拟支付、支付回调/确认、订单查询和管理员订单管理。
3. 使用唯一业务号和幂等机制，避免重复支付、重复发放权益。
4. 支付成功后按商品类型发放资料访问权、AI 次数或考试发布次数。
5. 实现额度查询和原子扣减，保证并发下不出现负数。
6. 开发商品购买、订单列表、模拟支付、我的权益/额度和后台订单页面。
7. 编写重复支付、重复回调、订单金额篡改、并发扣减和权限发放测试。

### 你需手动操作

1. 在后台或数据库中初始化三类测试商品及价格。
2. 使用测试账号完成模拟购买，核对订单、支付记录和用户权益。
3. 验证重复点击支付不会重复发放权益。
4. 确认 MVP 只保留模拟支付提示，避免用户误认为是真实交易。
5. 若改接真实支付，需由你申请商户、配置证书和回调域名，并另行进行安全评审。

### 完成标志

- 三类商品均可模拟支付并准确发放权益；资料访问及额度扣减正确。

## 阶段 7：AI 资料总结与知识讲解

**目标：** 在资料上下文内完成 AI 总结和多轮知识讲解，并正确计费。

### AI 开发

1. 抽象 AI 客户端，支持真实接口与本地模拟实现切换。
2. 实现图文和可提取文档的文本读取；视频首版仅使用发布者提供的文字说明或字幕，不做语音转写。
3. 实现 AI 总结任务：提取文本、调用模型、保存摘要/知识点/复习提纲、记录任务状态。
4. 实现基于当前资料的知识讲解、多轮会话及消息保存。
5. 限制输入长度、资料上下文长度、单次请求频率和并发，过滤敏感配置与异常堆栈。
6. 仅在 AI 调用成功并保存结果后原子扣减额度；失败不扣费，重复请求需防止重复扣减。
7. 记录 AI 使用明细，提供管理员 AI 开关、价格/次数配置和基础使用查询。
8. 开发 AI 学习助手、会话、额度提示和后台 AI 配置页面。
9. 编写无额度、接口超时、模型失败、重复提交和扣费一致性测试。

### 你需手动操作

1. 选择 AI 供应商和模型，在供应商控制台创建 API Key，并了解费用及内容政策。
2. 将 API Key、接口地址和模型名写入本机环境变量，不提交到仓库。
3. 若运行环境不能访问 AI 服务，配置网络或继续使用模拟 AI 服务验收其他流程。
4. 准备可合法用于测试的资料，人工评价摘要、知识点及讲解质量。
5. 检查供应商账单和调用量，为开发环境设置额度告警或限额。

### 完成标志

- 有权益用户可对资料生成总结并提问；成功调用扣额度、失败不扣额度；记录可追踪。

## 阶段 8：后台管理、日志与安全加固

**目标：** 补齐管理员功能，降低越权、数据泄露和恶意调用风险。

### AI 开发

1. 完成用户查询、启用/禁用、角色管理及必要的账号保护。
2. 完成内容审核、下架、分类管理、考试查看、订单管理和 AI 配置。
3. 对登录、内容审核、订单权益、考试发布、人工阅卷等关键操作记录操作日志。
4. 加入接口限流、上传白名单、文件大小限制、敏感字段脱敏和日志清理策略。
5. 检查 SQL 注入、XSS、CSRF 适用场景、水平/垂直越权、文件上传和 JWT 安全。
6. 完善全局异常提示、空状态、加载状态和关键操作二次确认。
7. 补充隐私数据及 AI 输入内容的最小化处理说明。

### 你需手动操作

1. 为生产环境生成高强度 JWT 密钥和各服务密码。
2. 使用三类账号逐页检查菜单和操作权限。
3. 检查日志中是否出现密码、Token、数据库密码、MinIO 密钥或 AI Key。
4. 人工验证禁用账号、内容驳回/下架、订单查询和操作日志。
5. 决定日志保留周期、用户上传内容规范和隐私告知文本。

### 完成标志

- 管理端核心页面可用；关键操作可审计；常见越权和敏感信息泄露问题已处理。

## 阶段 9：联调、测试、部署与验收

## 6. MVP 最终验收清单

- [ ] 发布者能够上传、编辑并提交学习资料。
- [ ] 管理员能够审核、驳回和下架学习资料。
- [ ] 用户能够查看免费资料，并在购买后查看付费资料。
- [ ] 学习进度、收藏、点赞和评论能够正常记录。
- [ ] 用户能够购买 AI 次数并使用资料总结和知识讲解。
- [ ] AI 成功调用扣减额度，调用失败不扣减。
- [ ] 发布者能够创建五种题型、固定试卷和考试。
- [ ] 发布者能够指定用户参加考试，并正确扣减考试发布次数。

- [ ] 单选、多选、判断题能够自动评分。
- [ ] 填空题能够自动评分或人工复核，简答题能够人工评分。

- [ ] 前后端构建及核心自动化测试通过，部署文档可在新环境复现。

## 7. 关键风险与控制措施

1. **考试数据丢失：** 答案定时保存，手动/自动交卷幂等，服务端掌握截止时间，最终数据落 MySQL。
2. **重复支付或重复扣费：** 使用唯一业务号、事务、状态条件更新和幂等校验。
3. **资源越权：** 后端同时校验角色、所有者、考生资格和用户权益，不能只依赖前端隐藏按钮。
4. **答案泄露：** 考生作答接口不返回正确答案和解析，成绩可见性服从考试配置。
5. **文件安全：** MinIO 存储桶保持私有，通过短期签名地址访问，并限制格式、大小和归属。
6. **AI 成本失控：** 开发环境限流、限制上下文长度、设置供应商预算，成功保存结果后才扣用户额度。
7. **密钥泄露：** 所有真实凭证放入环境变量或本地私有配置，仓库只保留示例占位符。
8. **范围膨胀：** 严格以本文件列出的 MVP 为范围，非 MVP 功能统一进入后续版本清单。
