## 3. 配置文件规则

- `backend/.env.example` 和 `frontend/learning_platform_frontend/.env.example` 仅展示变量名，可以提交到 Git。
- 真实密码和密钥通过 IDEA 运行配置、本机环境变量或未跟踪的 `.env` 文件保存。
- Spring Boot 默认不会自动读取普通 `.env` 文件；在项目未明确加入加载机制前，优先使用 IDEA 的 Environment variables。
- 前端 `VITE_` 开头的变量会进入浏览器构建结果，严禁存放数据库密码、JWT 密钥、MinIO Secret Key 或 DeepSeek API Key。
- 根目录 `数据库密码（开发使用）.txt` 已被忽略，不应继续用于保存密码。

## 4. IDEA 后端运行配置

后端工程创建完成后，在 IDEA 中打开：

`Run` → `Edit Configurations` → 后端 Spring Boot 启动配置 → `Environment variables`

参照 `backend/.env.example` 添加本机实际值。至少需要配置：

- `DB_URL`、`DB_USERNAME`、`DB_PASSWORD`
- `REDIS_HOST`、`REDIS_PORT`、`REDIS_PASSWORD`
- `MINIO_ENDPOINT`、`MINIO_ACCESS_KEY`、`MINIO_SECRET_KEY`、`MINIO_BUCKET`
- `JWT_SECRET`
- 登录防刷默认启用；仅受控本地调试时可设置 `LOGIN_PROTECTION_ENABLED=false`。阈值和时间窗口可通过 `LOGIN_MAX_ACCOUNT_FAILURES`、`LOGIN_MAX_IP_FAILURES`、`LOGIN_PROTECTION_WINDOW_MINUTES` 调整。
- 通用接口限流默认启用；一般接口、登录注册、上传请求的每分钟额度分别通过 `API_GENERAL_REQUESTS_PER_MINUTE`、`API_AUTH_REQUESTS_PER_MINUTE`、`API_UPLOAD_REQUESTS_PER_MINUTE` 调整。仅受控测试时可设置 `API_RATE_LIMIT_ENABLED=false`。
- 模拟 AI 默认使用 `AI_PROVIDER=mock`，可用 `AI_MOCK_MODEL` 修改非敏感的模拟模型标识。`AI_MOCK_SCENARIO` 支持 `success`、`failure`、`timeout`，`AI_MOCK_DELAY_MILLIS` 控制模拟响应延迟；修改后需重启后端。
- 真实 AI 联调时配置 `AI_PROVIDER=deepseek` 和 `DEEPSEEK_API_KEY`；学习总结和讲解默认保持 `DEEPSEEK_THINKING_ENABLED=false`，避免简单任务因思考模式显著变慢。
- AI 调用限制可通过 `AI_MAX_INPUT_CHARS`、`AI_MAX_CONTEXT_MESSAGES`、`AI_MAX_CONTEXT_CHARS`、`AI_REQUESTS_PER_WINDOW`、`AI_RATE_WINDOW_SECONDS`、`AI_MAX_CONCURRENT_PER_USER`、`AI_REQUEST_TIMEOUT_SECONDS` 调整；通常保持 `.env.example` 默认值即可。

开发初期保持 `AI_PROVIDER=mock`，可以在没有真实 API Key 的情况下完成业务开发。
切换为 `deepseek` 但未提供 `DEEPSEEK_API_KEY` 时，后端会拒绝启动，防止误配置。
真实调用建议保持连接超时 `DEEPSEEK_CONNECT_TIMEOUT_SECONDS=10`、供应商响应
等待 `DEEPSEEK_TIMEOUT_SECONDS=620`、统一任务超时
`AI_REQUEST_TIMEOUT_SECONDS=630`。DeepSeek 可能在排队期间使用 SSE keep-alive
保持最长约 10 分钟连接，因此不能再使用原来的 90 秒响应超时。
模拟超时时，应将 `AI_MOCK_SCENARIO=timeout`，并令 `AI_MOCK_DELAY_MILLIS`
大于 `AI_REQUEST_TIMEOUT_SECONDS × 1000`；模拟失败使用
`AI_MOCK_SCENARIO=failure`。完成异常测试后应恢复为 `success`。

## 5. VS Code 前端配置

前端默认通过 Vite 代理访问后端：

- 浏览器请求前缀：`/api`
- 开发代理目标：`http://localhost:8080`

通常不需要创建前端私有 `.env`。若端口发生变化，可复制 `.env.example` 为 `.env.local` 后修改；`.env.local` 已被 Git 忽略。

## 6. DeepSeek 配置

- 官方文档：<https://api-docs.deepseek.com/zh-cn/>
- Base URL：`https://api.deepseek.com`
- API Key 环境变量：`DEEPSEEK_API_KEY`
- 默认模型：`deepseek-v4-flash`
- 模型名通过 `DEEPSEEK_MODEL` 配置，不在 Java 代码中写死。

后端负责调用 DeepSeek。前端不得直接调用 DeepSeek，也不得接触 API Key。

## 7. 文件上传与 MinIO 规则

- MinIO 存储桶保持私有，不开放匿名访问。
- 单文件全局上限为 200 MB，每份学习资料最多关联 20 个文件。
- 对象名由后端生成，格式为 `content/{所有者ID}/{年}/{月}/{UUID}.{扩展名}`，不使用用户提交的原始路径。
- 封面支持 JPEG、PNG、WebP；正文支持 PDF、文本和常见 Office 文档；视频支持 MP4、WebM；附件支持 PDF、ZIP、文本和常见 Office 文档；字幕支持 SRT、VTT。
- 文件扩展名必须与 MIME 类型匹配。封面上限 10 MB、正文 50 MB、字幕 5 MB，视频和附件受 200 MB 全局上限约束。
- 预览和下载地址默认仅签名 10 分钟，且生成前必须校验资源所有者或管理员身份。
- 可通过 `UPLOAD_MAX_FILE_SIZE`、`UPLOAD_MAX_FILES_PER_CONTENT` 和 `UPLOAD_SIGNED_URL_TTL_MINUTES` 调整全局配置。

## 8. 安全检查

每次提交代码前确认：

1. `git status` 中没有 `.env`、本地配置、证书或密码文件。
2. 源码和日志中没有数据库密码、JWT 密钥、MinIO 密钥或 DeepSeek API Key。
3. 示例文件只包含明显的占位符。
4. 如果密钥曾被提交或发到聊天中，立即在对应服务轮换密钥，单纯删除文件并不能消除泄露风险。

## 9. MVP 数据与内容治理配置

- 操作日志默认保留 180 天，部署环境每周至少执行一次过期清理。
- 日志仅供管理员用于安全审计、故障排查和争议处理，不保存密码、JWT、API Key、
  文件正文或完整请求体。
- 发布者和学习者提交的内容应遵守基础内容规范；管理员可以驳回、下架或删除违规
  内容，并接受人工申诉。
- 注册或首次使用前应展示简明隐私告知并由用户主动确认。启用真实 DeepSeek 时，
  必须明确说明完成请求所需的资料文本、问题和上下文会发送给 AI 服务提供方。

完整规则、清理 SQL 和可直接用于 MVP 的告知文本见
`backend/docs/mvp-governance-policy.md`。正式上线前必须补充运营主体、联系方式、
第三方清单、服务地区和更精确的数据保存期限。
