# OP-173～OP-175 安全审查与回归说明

## 审查结论

| 风险 | 检查结果与控制措施 |
| --- | --- |
| SQL 注入 | MyBatis 查询均使用 `#{...}` 参数绑定；未使用 `${...}` 拼接用户输入。分页、状态和枚举参数均经过类型或 Bean Validation 校验。新增注入样式关键字回归测试。 |
| XSS | 普通资料、评论、题目和表单内容均由 Vue 文本插值渲染。唯一使用 `v-html` 的 AI Markdown 先经 DOMPurify 严格标签、属性和 URL 协议白名单净化；后端同时下发限制性 CSP。 |
| 水平越权 | 资料/文件按发布者校验，订单、权益、AI 会话按当前用户校验，考试按发布者归属或指定考生校验。对不存在或不属于当前用户的订单返回统一“订单不存在”，减少资源枚举信息。 |
| 垂直越权 | Spring Security 对 `/api/admin/**`、`/api/publisher/**` 分别执行管理员和发布者角色校验；服务层继续执行资源归属校验，不能只依赖前端菜单。 |
| JWT | 只接受服务器密钥签名的 JWT；验证签名、过期时间、必需声明、正数用户 ID、签发/过期先后关系和异常未来签发时间。每次请求重新读取账号状态及角色，因此禁用和角色变更立即生效。 |
| 文件上传 | 扩展名、MIME、文件头三层匹配；按用途限制类型、大小和数量；拒绝路径型文件名，服务端生成对象名，私有桶通过短时签名 URL 访问。新增伪装可执行文件测试。 |
| 答案泄露 | 考生作答 DTO 不含正确答案、解析及选项正确性；成绩仅在阅卷完成、考试结束且发布者允许时展示答案。发布者阅卷接口同时验证考试归属。 |
| 敏感信息 | 登录、配置及审计日志不记录密码、JWT 或正文；用户管理响应不返回密码哈希和登录 IP；AI 配置只返回是否已配置 API Key。 |

本轮未发现仍可直接利用的高风险 SQL 注入、存储型 XSS、常见横向/纵向越权或
提前获取考试答案路径。

## OP-174 界面完善

- 首页对 `/?forbidden=1` 显示明确的无权限提示。
- 路由资源加载失败进入独立 500 异常页；原 404 页面继续保留。
- 首页精选资料和资料编辑页增加加载失败、重试、空分类和空文件状态。
- 资料编辑表单提供分类、标题和付费价格的字段级错误信息。
- 管理员分配角色新增二次确认，且明确提示权限立即生效。
- 已有删除资料/文件/题库/题目/试卷、下架资料、发布/取消考试、提交试卷、
  模拟支付和完成阅卷等危险操作均保留二次确认。

## OP-175 自动化覆盖

安全回归覆盖以下场景：

- 普通用户访问发布者或管理员接口返回 403；
- 非所有者不能读取或修改其他发布者资料、订单、AI 会话和考试阅卷数据；
- 管理员禁用账号后旧 JWT 立即返回 401；
- 资料下架后详情、学习入口和公开列表立即不可访问；
- 用户、登录、AI 配置和操作日志响应不泄露密码、哈希、密钥或请求正文；
- SQL 注入样式搜索条件不会改变查询结构；
- 伪造、过期、未来签发或非法主体 JWT 被拒绝；
- 上传白名单、大小、数量、所有者和文件头检查；
- 考生未满足展示条件时不返回正确答案和解析。

执行方式：

```powershell
cd backend
mvn test
```

前端生产校验：

```powershell
cd frontend/learning_platform_frontend
npm run build
```

## OP-182～OP-184 阶段 I 收口复查

### 人工反馈修复

- 发布者资料编辑页已为封面、正文文件、视频、附件和字幕分别展示扩展名及
  单文件大小限制。
- 浏览器选择文件时会先执行用途对应的格式和大小检查；不符合规则时不发送
  上传请求。
- 上传请求使用独立的 10 分钟超时；Spring Multipart 超限统一返回 HTTP 413、
  业务码 `41300` 和明确的文件过大提示，不再误报“网络连接失败”。

### 依赖、配置与代码检查

- Maven 运行时依赖由 Spring Boot 3.5.16 BOM 管理；直接依赖保持 MyBatis
  3.0.5、JJWT 0.13.0、MinIO 9.0.1 和 OkHttp 5.3.2，本轮未跨大版本升级。
- 前端锁定安装版本包括 Vue 3.5.40、Axios 1.18.1、DOMPurify 3.4.12、
  Element Plus 2.14.3、Marked 18.0.7 和 Vite 8.1.5。已核对当前公开安全公告：
  当前 Axios 版本高于相关修复边界，Vite 版本高于任意文件读取问题的 8.0.5
  修复版本。本轮未发现必须变更依赖版本的阻断项。
- npm 国内镜像不提供 audit API，官方 audit API 本次检查返回 522，故不能把
  `npm audit` 作为本轮“零漏洞”的依据；后续 CI 应接入可用的 Dependabot、
  OSV 或 npm 官方审计服务持续检查传递依赖。
- 生产配置未包含实际密码或密钥，数据库、Redis、JWT、MinIO 和 DeepSeek
  凭证均从环境变量读取；Actuator 仅暴露 health/info 且不展示详情。
- 源码扫描未发现生产代码使用 `System.out`、`printStackTrace`、
  `console.log/debug` 输出敏感信息；唯一 AI `v-html` 输出继续经过 DOMPurify
  白名单净化。
- Vite 开发服务器监听局域网地址仅用于当前联调，不应作为生产服务器；
  正式部署必须发布 `npm run build` 生成的静态文件，并通过反向代理启用 HTTPS。
