# 智学云考部署指南

本文说明如何将当前 MVP 部署到一台 Linux 服务器。推荐架构为：

```text
浏览器
  ├─ https://learn.example.com/       Nginx 静态前端
  ├─ https://learn.example.com/api/   Nginx → Spring Boot :8080
  └─ https://files.example.com/       Nginx → MinIO API :9000

Spring Boot → MySQL :3306 / Redis :6379 / MinIO
```

Nginx 是唯一对公网开放的应用入口。MySQL、Redis、MinIO 控制台和 Spring Boot
端口不应直接暴露到公网。下文中的域名、账号和路径均为示例，必须替换。

## 1. 部署前准备

### 1.1 服务器建议

MVP 演示环境建议至少：

- Linux x86_64，2 核 CPU、4 GB 内存、40 GB 可用磁盘；
- JDK 21；
- MySQL 8.0；
- Docker Engine 与 Docker Compose v2（运行 Redis、MinIO）；
- Nginx；
- 可选 Node.js 22 和 Maven 3.9（若选择在服务器构建）。

生产数据量增加后，应独立评估数据库、MinIO 容量、带宽和备份空间。

### 1.2 域名与网络

准备两个域名并解析到服务器：

- `learn.example.com`：前端与后端 API；
- `files.example.com`：MinIO 文件上传、预览和下载。

防火墙只对公网开放：

- TCP 80：申请证书及跳转 HTTPS；
- TCP 443：业务访问；
- SSH 管理端口：限制来源 IP。

3306、6379、8080、9000、9001 只允许本机或受控内网访问。

### 1.3 目录规划

以下命令以 `/opt/learning-platform` 为应用目录：

```bash
sudo useradd --system --home /opt/learning-platform \
  --shell /usr/sbin/nologin learning-platform
sudo mkdir -p /opt/learning-platform/releases
sudo mkdir -p /etc/learning-platform
sudo mkdir -p /var/www/learning-platform
sudo mkdir -p /var/backups/learning-platform
sudo chown -R learning-platform:learning-platform /opt/learning-platform
sudo chmod 750 /etc/learning-platform
```

配置和密钥放在 `/etc/learning-platform`，不放进源码或前端目录。

## 2. 构建发布包

建议在已通过测试的构建机上构建，再上传产物。构建前确认工作区和版本：

```bash
git status
git rev-parse --short HEAD
```

### 2.1 后端

```bash
cd backend
mvn clean test
mvn clean package -DskipTests
```

产物：

```text
backend/target/learning-platform-backend-0.0.1-SNAPSHOT.jar
```

### 2.2 前端

同源部署保持 `VITE_API_BASE_URL=/api`：

```bash
cd frontend/learning_platform_frontend
npm ci
VITE_API_BASE_URL=/api npm run build
```

产物目录为 `dist/`。`VITE_` 变量会公开，不得包含数据库、JWT、MinIO 或 AI 密钥。

### 2.3 上传产物

以时间或提交号创建不可变发布目录：

```bash
sudo mkdir -p /opt/learning-platform/releases/20260724-01
sudo cp learning-platform-backend-0.0.1-SNAPSHOT.jar \
  /opt/learning-platform/releases/20260724-01/app.jar
sudo rsync -a --delete dist/ /var/www/learning-platform/
sudo chown -R learning-platform:learning-platform \
  /opt/learning-platform/releases/20260724-01
sudo ln -sfn /opt/learning-platform/releases/20260724-01 \
  /opt/learning-platform/current
```

若在 Windows 构建，可使用 `scp`、SFTP 或发布流水线上传 JAR 和 `dist` 内容。

## 3. 初始化 MySQL

### 3.1 创建数据库和专用账号

在数据库服务器执行，密码替换为随机强密码：

```sql
CREATE DATABASE IF NOT EXISTS `learning_platform`
    CHARACTER SET utf8mb4
    COLLATE utf8mb4_0900_ai_ci;

CREATE USER IF NOT EXISTS 'learning_platform'@'127.0.0.1'
    IDENTIFIED BY '<生产数据库强密码>';

GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, ALTER, INDEX, REFERENCES
    ON `learning_platform`.* TO 'learning_platform'@'127.0.0.1';
FLUSH PRIVILEGES;
```

数据库不在同一台主机时，将来源限制为应用服务器的内网地址，并启用数据库 TLS；
不要使用任意来源 `%`。

### 3.2 执行初始化脚本

全新数据库依次执行：

```bash
mysql --user=root --password learning_platform < database/001_schema.sql
mysql --user=root --password learning_platform < database/002_seed_data.sql
```

已有数据库不能用 `CREATE TABLE IF NOT EXISTS` 代替迁移。部署任何结构变更前必须先
备份，再编写并审核增量迁移 SQL。

检查：

```sql
SELECT COUNT(*) FROM information_schema.tables
WHERE table_schema = 'learning_platform';
SELECT code, name FROM learning_platform.role ORDER BY id;
```

应有 33 张业务表和三个基础角色。

## 4. 部署 Redis 与 MinIO

`infrastructure/docker-compose.local.yml` 已将端口绑定到 `127.0.0.1`，可用于单机
MVP。复制环境文件：

```bash
cd /opt/learning-platform/source
cp infrastructure/.env.example infrastructure/.env
chmod 600 infrastructure/.env
```

替换全部占位符后启动：

```bash
docker compose --env-file infrastructure/.env \
  -f infrastructure/docker-compose.local.yml up -d
docker compose --env-file infrastructure/.env \
  -f infrastructure/docker-compose.local.yml ps
```

部署前应把 `docker-compose.local.yml` 中的 MinIO `latest` 固定为本次验证过的明确
版本或镜像 digest，避免重启时意外升级。

### 4.1 创建 MinIO 私有存储桶

通过 SSH 隧道临时访问控制台，不要开放 9001：

```bash
ssh -L 9001:127.0.0.1:9001 deploy@your-server
```

本机浏览器打开 `http://127.0.0.1:9001`，创建私有存储桶
`learning-platform`。生产环境建议再创建仅有该桶读写权限的应用服务账号，不让后端
长期使用 MinIO root 凭证。

### 4.2 检查依赖

```bash
docker compose --env-file infrastructure/.env \
  -f infrastructure/docker-compose.local.yml exec redis \
  sh -c 'redis-cli -a "$REDIS_PASSWORD" ping'
curl -fsS http://127.0.0.1:9000/minio/health/live
```

预期分别返回 `PONG` 和成功状态。

## 5. 配置后端

复制生产模板：

```bash
sudo cp infrastructure/production/backend.env.example \
  /etc/learning-platform/backend.env
sudo chown root:learning-platform /etc/learning-platform/backend.env
sudo chmod 640 /etc/learning-platform/backend.env
sudo editor /etc/learning-platform/backend.env
```

必须替换模板中的：

- 数据库密码；
- Redis 密码；
- MinIO 应用账号和密钥；
- 至少 32 字节、生产环境独立生成的 JWT Secret；
- 两个正式 HTTPS 域名；
- 使用真实 AI 时的 DeepSeek API Key。

生成 JWT Secret 的一种方式：

```bash
openssl rand -base64 48
```

不要把输出粘贴到源码、聊天、工单或 shell 历史。真实 AI 未准备好时保持
`AI_PROVIDER=mock`；切换为 `deepseek` 后必须提供有效 Key。

`MINIO_ENDPOINT` 必须是浏览器能够访问的 HTTPS 文件域名
`https://files.example.com`，因为预签名 URL 会包含该主机名。若写成
`http://127.0.0.1:9000`，服务器自身可以访问，但用户浏览器无法下载文件。

## 6. 使用 systemd 运行后端

安装服务模板：

```bash
sudo cp infrastructure/production/learning-platform.service \
  /etc/systemd/system/learning-platform.service
sudo systemctl daemon-reload
sudo systemctl enable learning-platform
sudo systemctl start learning-platform
sudo systemctl status learning-platform
```

查看日志：

```bash
sudo journalctl -u learning-platform -n 200 --no-pager
sudo journalctl -u learning-platform -f
```

后端只监听 `127.0.0.1:8080`。本机检查：

```bash
curl -fsS http://127.0.0.1:8080/api/health
curl -fsS http://127.0.0.1:8080/actuator/health/readiness
```

readiness 必须为 `UP` 后才配置公网流量。

## 7. 准备 Nginx 配置

复制模板：

```bash
sudo cp infrastructure/production/nginx.learning-platform.conf \
  /etc/nginx/sites-available/learning-platform
sudo editor /etc/nginx/sites-available/learning-platform
```

将所有 `learn.example.com`、`files.example.com` 替换为实际域名。该模板直接使用
HTTPS，因此此时先不要创建 `sites-enabled` 链接；完成下一节的证书申请后再启用。

模板已经包含：

- Vue Router history 模式的 `try_files ... /index.html`；
- `/api/` 到 Spring Boot 的反向代理；
- AI 长请求所需的 700 秒读取超时；
- 与后端一致的 220 MB 请求上限；
- MinIO 独立文件域名代理；
- 常用安全响应头。

不要公开代理 `/actuator/`；readiness 由服务器本机或受控监控系统访问。

## 8. 申请 HTTPS 证书并启用站点

确认两个域名已解析且 80/443 可达。模板为两个域名使用独立证书，首次申请时使用
standalone 模式；它会临时监听 80 端口：

```bash
sudo systemctl stop nginx
sudo certbot certonly --standalone -d learn.example.com
sudo certbot certonly --standalone -d files.example.com
sudo ln -sfn /etc/nginx/sites-available/learning-platform \
  /etc/nginx/sites-enabled/learning-platform
sudo nginx -t
sudo systemctl start nginx
sudo certbot renew --dry-run
```

若证书申请失败，应先重新启动 Nginx，避免站点长时间中断。证书成功后确认 HTTP
自动跳转 HTTPS。若使用云负载均衡或其他证书平台，应在其上完成同等配置，并保证
代理向后端传递 `X-Forwarded-Proto`、`Host` 和客户端地址。

## 9. 创建首个管理员

平台没有默认管理员密码。部署后：

1. 通过正式页面注册一个专用管理账号；
2. 在数据库确认用户名；
3. 执行一次角色授权；
4. 重新登录；
5. 限制数据库管理权限，不再通过 SQL 日常修改角色。

```sql
INSERT IGNORE INTO learning_platform.user_role (user_id, role_id)
SELECT u.id, r.id
FROM learning_platform.user u
JOIN learning_platform.role r ON r.code = 'ADMIN'
WHERE u.username = '<管理员用户名>';
```

## 10. 上线检查

### 10.1 服务状态

```bash
systemctl is-active learning-platform nginx mysql
docker compose --env-file infrastructure/.env \
  -f infrastructure/docker-compose.local.yml ps
```

### 10.2 HTTP 检查

```bash
curl -fsS https://learn.example.com/
curl -fsS https://learn.example.com/api/health
curl -fsS https://files.example.com/minio/health/live
```

浏览器继续验证：

1. 注册、登录、退出；
2. 三类角色菜单和越权阻止；
3. 资料上传、审核、预览和下载；
4. 考试创建、作答、交卷和阅卷；
5. 模拟购买与权益发放；
6. Mock 或真实 AI 总结和连续讲解；
7. 管理后台操作日志。

检查浏览器控制台无混合内容、CORS、404 或 502。

## 11. 更新发布

每次发布先执行：

```bash
cd backend && mvn test
cd ../frontend/learning_platform_frontend && npm test && npm run build
```

备份后创建新发布目录，例如 `/opt/learning-platform/releases/20260725-01`，上传新
JAR，再切换软链接：

```bash
sudo ln -sfn /opt/learning-platform/releases/20260725-01 \
  /opt/learning-platform/current
sudo systemctl restart learning-platform
curl -fsS http://127.0.0.1:8080/actuator/health/readiness
```

前端使用 `rsync -a --delete dist/ /var/www/learning-platform/` 更新。若包含数据库
变更，必须在应用切换前后按迁移方案执行，不能直接重跑结构脚本。

## 12. 备份与恢复

### 12.1 MySQL

```bash
mysqldump --single-transaction --routines --triggers \
  --user=backup_user --password learning_platform \
  | gzip > /var/backups/learning-platform/mysql-$(date +%F-%H%M).sql.gz
```

恢复必须先在隔离数据库演练：

```bash
gunzip -c backup.sql.gz | mysql --user=root --password learning_platform_restore
```

### 12.2 MinIO

安装 MinIO Client 后配置受限别名，再执行：

```bash
mc mirror --overwrite production/learning-platform \
  /var/backups/learning-platform/minio/
```

数据库和 MinIO 应采用相近时间点备份，否则文件元数据可能不一致。备份目录需要加密、
限制访问并定期执行恢复演练。

### 12.3 操作日志

`operation_log` 默认保留 180 天。每周按
`backend/docs/mvp-governance-policy.md` 中的 SQL 清理；安全事件或争议相关日志可
受控延期保留。

## 13. 回滚

1. 发现异常后停止继续迁移和写入；
2. 查看 `journalctl`、Nginx error log 和请求 traceId；
3. 若数据库结构向后兼容，切回上一发布目录并重启；
4. 若结构不兼容，按已审核的回滚 SQL 或备份恢复方案处理；
5. 恢复后执行 readiness 和核心冒烟测试。

```bash
sudo ln -sfn /opt/learning-platform/releases/<上一版本> \
  /opt/learning-platform/current
sudo systemctl restart learning-platform
```

不得在没有数据库备份的情况下回滚破坏性结构变更。

## 14. 常见部署故障

### Nginx 返回 502

- `systemctl status learning-platform`；
- `curl http://127.0.0.1:8080/api/health`；
- 检查 JAR 路径、Java 版本和 `/etc/learning-platform/backend.env` 权限。

### API 返回 403 或浏览器出现 CORS

- `APP_CORS_ALLOWED_ORIGINS` 必须是完整来源，如 `https://learn.example.com`；
- 不要填写路径或末尾 `/`；
- 检查 Nginx 是否保留 `Host` 和 `X-Forwarded-Proto`；
- 修改环境变量后重启后端。

### 文件 URL 指向 localhost 或出现混合内容

将 `MINIO_ENDPOINT` 改为 `https://files.example.com`，确认文件域名证书和 Nginx
代理正常，然后重启后端。旧的短期预签名 URL 过期后重新获取即可。

### 上传返回 413

确认 Nginx `client_max_body_size 220m`、Spring `max-request-size: 220MB` 和用途级
限制一致。页面各用途上限仍优先适用，不能通过调高 Nginx 绕过业务限制。

### AI 请求被 504 或前端超时

- Nginx `proxy_read_timeout` 应大于后端 630 秒任务超时；
- 检查 DeepSeek Key、模型、服务器出站 HTTPS 和系统时间；
- 用同一 traceId 对照后端 `AI_PROVIDER_*` 日志；
- 失败后确认平台没有扣除 AI 额度。

### readiness 为 DOWN

从返回的组件状态定位 MySQL、Redis 或 MinIO，检查账号、网络、存储桶和容器健康。
不要把详细 Actuator 信息开放到公网。
