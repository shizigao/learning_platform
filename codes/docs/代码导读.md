# 代码导读与注释约定

## 1. 后端阅读顺序

从某个 `web/*Controller` 找到入口，再沿构造器依赖进入 `service`；Service 使用 `mapper` 读写 `domain`，并返回 `dto`。复杂规则优先阅读测试，测试文件通常直接展示完整业务场景。

重要公共入口：

- `common/api/ApiResponse.java`：统一响应。
- `common/exception/GlobalExceptionHandler.java`：异常到 HTTP/业务码的映射。
- `auth/security/JwtAuthenticationFilter.java`：Token 认证。
- `content/service/ContentAccessService.java`：资料访问权。
- `exam/service/CandidateExamSessionService.java`：考试会话。
- `ai/service/AiTaskLifecycleService.java`：AI 幂等任务。
- `order/service/EntitlementService.java`：权益余额与发放。

## 2. 前端阅读顺序

从 `router/index.ts` 找页面，在 `views` 中查看编排，再查对应 `api/*.ts` 和 `types/*.ts`。通用交互优先在 `components` 和 `utils` 中复用。

关键全局状态：

- `auth.user`：当前用户；`null` 表示无有效会话。
- `auth.initialized`：是否完成首次 Token 校验，防止路由守卫重复请求。
- `auth.initializationPromise`：合并并发初始化。
- `ApiError.code/status/traceId`：分别表示业务码、HTTP 状态和后端追踪号。
- AI 页面 `sending/generating`：互斥长请求，避免重复扣次。

## 3. 注释规范

- 类/组件头说明“负责什么”和“不负责什么”。
- 公共函数说明参数、返回值、副作用、权限或幂等约束。
- 变量注释解释状态含义和不变量，不重复变量名。
- SQL 注释说明权限边界、快照或锁的目的。
- 不给赋值、循环等显而易见语句逐行注释；修改逻辑时同步修改注释。

## 4. 常见扩展

- 新页面：增加 `types` → `api` → `view` → `router`，需要角色时配置 `meta.roles`。
- 新后端业务：增加 DTO/Domain/Mapper/Service/Controller，并写集成测试。
- 新 AI 能力：新增 `AiTaskType`，复用任务、守卫、持久化和额度服务。
- 新权益：同时修改产品类型、权益类型、商品映射、余额 DTO 和前端商城。
- 新文件类型：同步后端白名单、前端提示、Nginx 大小限制和安全检查。

## 5. 后端逐文件注释索引

后端每个领域模块根目录的 `package-info.java` 均包含“文件职责索引”，覆盖该模块
所有 `domain`、`dto`、`mapper`、`service`、`web`、`config` 等源码。新开发者可先
在模块索引中定位文件，再进入具体文件阅读：

- 文件开头：说明文件职责、所属模块、所在分层和联动维护范围。
- 顶层类型：说明类型作用及职责边界。
- 字段/常量：说明保存的状态、依赖或安全约束。
- 函数/接口方法：说明查询、写入、状态流转、权限、事务或外部调用语义。

仓库提供 [`tools/annotate-backend.ps1`](../tools/annotate-backend.ps1) 用于检查并补齐
缺失注释。默认仅预览变更，确认后使用：

```powershell
.\tools\annotate-backend.ps1
.\tools\annotate-backend.ps1 -Apply
```

脚本具有幂等性，保留已有人工 Javadoc，并跳过 Java `"""` 文本块，防止改动
Mapper SQL 或 AI 提示词。自动注释用于建立一致基线；新增复杂业务规则时仍应由
开发者补充参数含义、异常条件、事务边界和不变量。
