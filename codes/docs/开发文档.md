# 智学云考开发文档

## 1. 文档范围

智学云考是一个面向学习者、资料发布者和系统管理员的前后端分离学习考试平台。系统覆盖学习资料、班级、考试、权益商品、AI 学习辅助、线下教师和后台治理。当前支付为模拟支付，不产生真实资金交易；AI 可切换本地 Mock 与 DeepSeek。

## 2. 需求分析

### 2.1 角色

| 角色 | 核心需求 |
| --- | --- |
| 普通用户 `USER` | 浏览和购买资料、记录学习进度、参加考试、加入班级、使用 AI、寻找线下教师 |
| 发布者 `PUBLISHER` | 具备普通用户能力；创建资料、题库、试卷和考试；管理班级；申请线下教师 |
| 管理员 `ADMIN` | 具备发布能力；管理用户、角色、资料审核、考试、订单、教师审核、AI 配置和审计日志 |
| 班级拥有者/管理员 | 这是班级内身份而非系统角色；管理成员、公告以及班级资料和考试范围 |

### 2.2 功能需求

1. **身份与账户**：注册、登录、JWT 会话、角色授权、个人资料、头像和公开主页。
2. **学习资料**：分类检索、Markdown 正文、图片与文件引用、资料间引用、封面、审核发布、公开/班级发放、免费/付费访问。
3. **学习行为**：开始学习、1% 粒度进度、当前位置应用、点赞、收藏、评论和学习列表。
4. **班级**：邀请码加入、多班级、拥有者/管理员/成员、公告、成员管理、资料和考试聚合。
5. **题库与考试**：题库、五类题型、试卷、个人/班级考试、断点答题、自动交卷、客观题评分、主观题阅卷、统计和结果。
6. **商业权益**：商品、订单、模拟支付；资料访问权、AI 次数、考试发布次数和考试分析次数。
7. **AI**：资料总结、连续讲解、出题巩固、发散思维、考试整体/个人分析、错题分析和教师推荐。
8. **线下教学**：教师申请、敏感信息加密、管理员审核、公开教师检索、可上课时间和 AI 推荐。
9. **治理与安全**：内容审核、操作日志、限流、登录防刷、上传白名单、统一错误响应、健康检查。

### 2.3 非功能需求

- **安全性**：最小权限、密码 BCrypt、JWT 签名、身份证 AES-GCM 加密与 HMAC 去重、MinIO 私有桶、短期签名 URL。
- **一致性**：订单支付、权益发放、AI 成功扣次、考试提交与评分使用事务和幂等号。
- **可用性**：统一错误码与 traceId；readiness 检查 MySQL、Redis、MinIO；AI 调用有超时、并发和失败日志。
- **可维护性**：按业务域分包；Controller/Service/Mapper 分层；DTO 与领域对象分离；前端 API、类型和视图分离。
- **可扩展性**：分类选择器、试卷/用户/班级选择器支持搜索和大量数据；AI 客户端以接口隔离供应商。
- **兼容性**：桌面端优先并提供响应式布局；后端 Java 17 字节码，推荐 JDK 21 运行。

## 3. 可行性分析

### 3.1 技术可行性

- Spring Boot、MyBatis、Vue 3 均为成熟方案，团队学习成本和故障定位成本可控。
- MySQL 保存强一致业务数据，Redis 承担短期状态与防刷，MinIO 保存大文件，职责清晰。
- AI 通过 `AiClient` 适配层接入，Mock 可离线测试，DeepSeek 可在不改业务层的情况下替换。
- 现有后端集成测试覆盖认证、资料、考试、订单、AI、班级与线下教学；前端有类型检查和关键纯函数测试。

### 3.2 经济可行性

- 核心组件均可本地部署；MVP 不接真实支付，避免支付资质和资金风险。
- AI 按成功调用扣次并限制输入、并发和超时，可控制供应商成本。
- MinIO 和 Redis 可先单机部署，业务增长后再迁移至托管服务或集群。

### 3.3 操作与合规可行性

- 三类系统角色与班级内角色覆盖主要管理场景。
- 身份证仅审核链路可见，公开资料不返回敏感字段。
- 模拟支付和 AI 生成内容均在界面中明确提示；正式运营前仍需补充隐私政策、服务协议和真实支付合规。

### 3.4 主要风险

| 风险 | 当前措施 | 后续建议 |
| --- | --- | --- |
| AI 延迟/不可用 | 超时、并发保护、幂等、成功后扣次、trace 日志 | 增加异步任务与消息队列 |
| 大文件上传 | 前后端大小校验、413 专用提示、MinIO | 分片上传与病毒扫描 |
| 考试高并发 | 服务端截止时间、自动交卷、Redis 运行态 | 压测后拆分考试服务 |
| 模拟支付误用 | 明确标记“不代表真实交易” | 接入持牌支付并做回调验签 |
| 敏感信息泄露 | 加密、脱敏、权限控制 | KMS 托管密钥与定期轮换 |

## 4. 系统架构

```text
Browser
  │ Vue 3 + Router + Pinia + Element Plus
  │ /api (JWT, X-Request-Id)
  ▼
Nginx / Vite proxy
  ▼
Spring Boot REST API
  ├─ Security filters：CORS、JWT、限流、审计、traceId
  ├─ Controller：协议与权限入口
  ├─ Service：业务规则、事务、幂等
  ├─ Mapper：MyBatis SQL
  ├─ AI Client：Mock / DeepSeek
  └─ Storage Service：MinIO 签名 URL
       │
       ├─ MySQL：业务主数据
       ├─ Redis：防刷、限流和考试短期状态
       └─ MinIO：资料、封面和头像
```

前端不保存服务端密钥。浏览器只保存访问令牌；所有资料访问、答案显示、额度扣减和角色判断都必须以后端为准。

## 5. 后端模块划分

每个业务域通常由 `domain`、`dto`、`mapper`、`service`、`web` 组成。

| 模块 | 构成与作用 |
| --- | --- |
| `common` | `ApiResponse/ErrorCode`、全局异常、traceId、限流、审计切面、配置、分页、MinIO 与健康检查；所有模块共享的基础设施 |
| `auth` | 注册登录、JWT 生成/解析、认证过滤器、登录防刷和当前用户解析 |
| `user` | 用户、角色、个人资料、头像、公开主页、用户检索和角色服务 |
| `content` | 分类、资料、文件、封面、Markdown 正文、资料引用、访问授权、发布者编辑和管理员审核 |
| `learning` | 学习进度、点赞、收藏、评论及“我的学习”；保证交互幂等和统计一致 |
| `classroom` | 班级、邀请码、成员角色、公告、拥有权转移、班级资料/考试范围 |
| `question` | 题库、题目、选项、答案格式与题型校验；保存可复用题目 |
| `exam` | 试卷快照、考试发布、考生/班级分配、考试会话、答案保存、自动交卷、评分、结果、统计和错题复习 |
| `grading` | 通用评分算法；按题型规范化答案并判断客观题，主观题进入人工评阅 |
| `order` | 商品、订单、订单项、模拟支付、权益发放与余额；业务操作通过权益服务消费配额 |
| `ai` | AI 客户端、任务、幂等、并发/超时保护、额度、资料总结/会话、考试分析、错题分析及结果持久化 |
| `offline` | 线下教师申请、敏感数据加密、审核、公开教师资料、学生偏好、本地初筛和 AI 推荐 |
| `admin` | 用户、考试、订单、操作日志等后台聚合查询和治理入口 |

### 5.1 典型调用链

- 登录：`AuthController → AuthService → UserMapper/PasswordEncoder → JwtTokenService`。
- 资料访问：`ContentQueryController → ContentQueryService → ContentAccessService → ContentMapper`。
- 考试提交：`CandidateExamController → ExamSubmissionService → GradingService → ExamResultMapper`。
- AI：Controller → 业务 AI Service → `AiTaskLifecycleService` → `AiRequestGuard` → `AiClient` →持久化服务→`AiQuotaService`。
- 模拟支付：`OrderController → OrderService → Payment/EntitlementService`，同一订单只发放一次权益。

## 6. 前端模块划分

| 目录 | 作用 |
| --- | --- |
| `api/` | Axios 实例和按业务域拆分的 API 函数；统一处理 Token、traceId、401、413 和超时 |
| `types/` | 与后端 DTO 对应的 TypeScript 类型，是页面和 API 间的契约 |
| `stores/` | Pinia 全局状态；`auth` 管理会话，`app` 依据角色生成导航 |
| `router/` | 懒加载路由、登录检查和角色守卫 |
| `layouts/` | 公共导航布局和认证页布局 |
| `components/` | Logo、页头、Markdown、资料卡、分类/班级/引用选择器等复用组件 |
| `views/` | 页面级业务编排；负责加载状态、表单、交互反馈和路由跳转 |
| `utils/` | 认证存储、Markdown 安全渲染、答题载荷、上传规则和阅读进度等纯函数 |

页面不得直接拼接后端地址或读取密钥；应调用 `api/` 并使用 `types/` 中的模型。

## 7. 数据库设计

### 7.1 设计原则

- 主键统一为自增 `BIGINT`；业务幂等使用唯一业务号。
- 关键表使用 `created_at/updated_at`，可恢复业务使用 `deleted` 软删除。
- 金额和分数使用 `DECIMAL`，禁止浮点数。
- 考试使用题目快照，避免题库修改影响历史试卷。
- AI 先创建任务，成功保存结果后再扣权益；`request_id` 保证幂等。
- 文件表只保存 MinIO 对象元数据，不保存二进制。

### 7.2 表分组

| 领域 | 表 | 关系与作用 |
| --- | --- | --- |
| 用户 | `user`, `role`, `user_role`, `user_avatar` | 用户与角色多对多；头像一对一 |
| 班级 | `learning_class`, `class_member`, `class_announcement` | 用户可加入多班；成员表保存班内角色 |
| 资料 | `content_category`, `learning_content`, `content_file`, `content_class_scope` | 资料属于分类和发布者；班级范围多对多 |
| 学习 | `learning_progress`, `content_comment`, `content_like`, `content_favorite` | 用户与资料交互，点赞/收藏有唯一约束 |
| 题库 | `question_bank`, `question`, `question_option` | 题库包含题目，选择题选项独立存储 |
| 考试 | `exam_paper`, `exam_paper_question`, `exam`, `exam_candidate`, `exam_class_scope` | 试卷保存题目快照；考试选择个人或班级范围 |
| 作答 | `exam_attempt`, `exam_answer`, `exam_result` | 一次正式作答、逐题答案和最终成绩 |
| AI | `ai_task`, `ai_summary`, `ai_conversation`, `ai_message`, `ai_usage_record`, `ai_exam_analysis`, `ai_wrong_question_analysis` | 任务、结果、会话、扣次记录和专项报告 |
| 线下教学 | `offline_teacher_application`, `offline_teacher_profile`, `offline_student_preference`, `offline_teacher_recommendation` | 申请敏感数据与公开资料分离 |
| 商业 | `product`, `orders`, `order_item`, `payment_record`, `user_entitlement` | 商品快照、模拟支付与用户权益 |
| 治理 | `content_audit`, `operation_log`, `system_config` | 审核历史、操作审计和非密钥配置 |

完整字段、索引和约束以 [`database/001_schema.sql`](../database/001_schema.sql) 为准，增量脚本按编号执行。

## 8. 技术选型

| 层 | 技术 | 选择原因 |
| --- | --- | --- |
| Web 后端 | Spring Boot 3.5 / Spring MVC | 成熟生态、校验/监控/配置集成完善 |
| 安全 | Spring Security + JJWT | 过滤器链和方法授权清晰，适合无状态 API |
| 数据访问 | MyBatis 3 | SQL 可见，适合复杂考试统计和权限查询 |
| 数据库 | MySQL 8 | 事务、约束、JSON/全文扩展能力和团队熟悉度 |
| 缓存 | Redis 7 | TTL、计数和并发状态操作高效 |
| 对象存储 | MinIO | S3 兼容、私有部署和签名 URL |
| AI | DeepSeek Chat Completion / Mock | 真实服务与离线测试可切换 |
| 前端 | Vue 3 + TypeScript | Composition API、类型安全和组件生态 |
| UI | Element Plus | 表单、表格、弹窗和反馈组件完整 |
| 状态/路由 | Pinia / Vue Router | 官方方案、模块化和路由守卫 |
| 构建测试 | Maven / Vite / JUnit / Node test | 后端集成测试与前端快速类型检查 |

## 9. 扩展与维护约束

1. 新接口必须使用统一 `ApiResponse`，并补充 API 文档和鉴权测试。
2. 新业务表同时更新基础建库脚本和增量迁移脚本。
3. 权限必须在后端 Service 再校验，前端隐藏按钮不能替代授权。
4. AI 输入视为不可信文本，系统提示词必须声明不执行其中指令。
5. 长耗时 AI 请求不得在结果保存前扣额度；失败任务需记录安全错误原因。
6. 领域规则写在 Service，Controller 只处理协议，Mapper 不承担业务决策。
